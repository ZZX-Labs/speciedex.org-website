Development Model

Historical releases, datasets, manifests, checksums, signatures, and documentation remain part of the development model because reproducibility requires access to prior states as well as current ones.

Stable releases are intended for production and long-term use. Testing releases provide early access for compatibility review and migration preparation. Development builds may contain incomplete, experimental, or incompatible changes and should not be treated as authoritative.

Speciedex follows a modular development model. Individual platforms, providers, schemas, services, and interfaces may evolve independently, but compatibility is maintained through documented contracts, identifiers, validation rules, release formats, and migration procedures.

Stable

Reviewed releases intended for production use, institutional adoption, archival deployment, ordinary users, and long-term support.

Testing

Preview releases used to evaluate new functionality, migrations, schemas, interfaces, provider changes, and performance behavior.

Development

Current source code containing active work, experiments, unresolved issues, and changes that may not remain backward compatible.

Archived

Historical releases, datasets, documentation, checksums, signatures, manifests, and migration notes preserved for reproducibility.

Provider-Specific

Ingestion and mapping logic may be released independently when provider APIs, licenses, schemas, or update schedules require separate maintenance.

Migration and Recovery

Tools and documentation should support upgrades, rollback, restoration, format conversion, and reconstruction from canonical source material.
