Core Principles

These principles define how the project should behave in practice. They guide software architecture, provider ingestion, scientific review, public interfaces, archival policy, governance, and institutional participation.

Open Source

Software, schemas, build logic, validation rules, and technical documentation should remain transparent, auditable, reproducible, and available under permissive licensing wherever the project controls them.

Scientific Integrity

Claims should remain traceable to providers, published literature, taxonomic authorities, specimens, genetic repositories, conservation assessments, and reviewable research methods.

Provider Provenance

Imported values should retain their source, original identifier, license, retrieval time, transformation history, validation state, and relationship to any canonical Speciedex record.

Long-Term Preservation

Data, software, schemas, documentation, media, and historical classifications should remain portable and recoverable across institutions and technologies.

Open Standards

Stable identifiers, documented APIs, common schemas, export formats, and versioned specifications should enable independent implementations and reuse.

Independent Verification

Releases, archives, datasets, and software should be verifiable through checksums, signatures, manifests, tests, source references, and reproducible builds.

Distributed Infrastructure

Mirrors, archives, independent operators, and redundant public services should reduce dependence on any one server, company, institution, or jurisdiction.

Community Collaboration

Researchers, developers, educators, institutions, archivists, operators, and volunteers should be able to contribute through documented and reviewable processes.
