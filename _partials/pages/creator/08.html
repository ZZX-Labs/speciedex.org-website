Commitment to Open Development

Wherever practical, software developed for Speciedex is intended to follow open standards, public source control, transparent documentation, reproducible builds, versioned releases, published checksums, and collaborative development practices.

Open development makes technical choices inspectable and permits independent implementations, audits, migrations, mirrors, and archival copies. It also allows mistakes to be found and corrected by people outside the original development process.

Contributions, constructive criticism, peer review, provider corrections, documentation improvements, translations, accessibility work, testing, security reports, infrastructure support, and scientific collaboration are all welcomed when they preserve provenance and follow documented project procedures.

Public Source

Code, issues, release notes, schemas, and build workflows should remain available for inspection and reuse.

Reviewable Changes

Material changes should identify their purpose, affected systems, migration requirements, and validation results.

Reproducible Releases

Published artifacts should be connected to source history, checksums, signatures, manifests, and documented build steps.

Independent Implementations

Open schemas and protocols should allow others to create compatible tools without depending on one private service.
