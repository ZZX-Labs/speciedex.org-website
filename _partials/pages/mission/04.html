Our Response

Build shared, verifiable infrastructure rather than another isolated database.

The response is deliberately modular. The public index, core data systems, explorer, network, web interface, terminal, library, archives, genetic references, analysis, maps, applications, and API all serve different needs while sharing a common canonical foundation.

The project instead provides open infrastructure capable of connecting those resources through stable identifiers, documented schemas, transparent provenance, public software, interoperable APIs, reproducible datasets, independently verifiable releases, portable archives, and distributed mirrors.

Speciedex is not intended to replace museums, universities, journals, government databases, conservation systems, taxonomic authorities, repositories, collections, or existing biodiversity networks.

Index

Connect accepted names, synonyms, classifications, publications, specimens, genetics, media, distributions, and external identifiers.

Verify

Preserve authorities, citations, licenses, validation states, revision history, checksums, signatures, manifests, and source references.

Preserve

Publish portable archives, historical releases, open formats, provider snapshots, and independently maintainable mirrors.

Distribute

Provide public browsing, downloads, APIs, terminal access, applications, offline archives, and low-bandwidth access where practical.

Compare

Expose provider differences, competing classifications, uncertainty, temporal change, and unresolved conflicts without erasing provenance.

Collaborate

Create shared workflows for researchers, developers, institutions, educators, conservationists, archivists, operators, and volunteers.

Educate

Make biodiversity information understandable and useful to students, teachers, communities, policymakers, and the public.

Protect

Balance openness with conservation risk, privacy, licensing, ethics, cultural responsibility, and source-specific restrictions.
